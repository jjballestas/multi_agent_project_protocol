## The SLIP, documented falsifiably

Acceptance criterion E5 (task file, line 22) requires: "una prueba negativa (estado gobernado
roto staged) aborta el commit en esa instancia." The reviewer's decisive question repeats it:
"el hook engancha de verdad (prueba negativa aborta)". I exercised the WHOLE family the
criterion promises, not only the given example (TASK_INDEX.json):

- Sandbox `/d/ccv266b`, fresh instance, clean baseline commit.
- Break `Area_comun/state/CLAIMS.json` (a governed-state file that `check_commit_trailers.py`
  does NOT read), stage it, commit with a VALID trailer (`Task-Id: none` + `Ops-Reason`).
- Result: `git commit` EXIT 0. The broken governed state (`{broken`) LANDS at HEAD.
  `validate_collaboration_state.py` on the resulting tree -> EXIT 1 (red).

Root cause: the shipped default hook mode is partial (E6-A cost split, pre-existing in
`.githooks/pre-commit`, which is TASK-0257 territory and correctly NOT touched here). In partial
mode the pre-commit runs `prune_state.py --check`, and on a governed-state error it prints
"protocol state pruning is due; local commit continues." and CONTINUES (does not reject). Full
governed-state validation is opt-in locally (`HOOK_FULL=1` or `git config hook.full true`) or in
clean-clone CI. So a newly-instanced hook does NOT hard-reject broken governed state by default;
the one case that appears to (TASK_INDEX.json) only fails because the trailer checker chokes on
the malformed JSON - an incidental crash, not a gate.

Net: the wiring deliverable (E4 + core.hooksPath + H1 verify default) is correct, but the E5
negative test is a false-positive that would pass even if the governed-state gate were absent,
and the family-level guarantee ("broken governed state staged aborts the commit") is FALSE by
default. Signing GO would implicitly certify a gate that does not fire in the general case.
