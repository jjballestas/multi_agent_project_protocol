# SPEC-0047 - D2.2: upgrade_instance tier-aware + runtime_version

## 1. Linea base

`scripts/upgrade_instance.py` (+ .ps1) es inform-only: compara `*.template.*` + `scripts/*.py/.ps1` +
`profiles/PROFILE_TEMPLATE/**` (DEFAULT_ADOPTABLE_GLOBS) entre master e instancia y reporta deltas
(nuevo/cambiado/igual/eliminado); la adopcion la decide la instancia (DECISION-0006). HOY **no incluye
`runtime/**`** => una instancia del tier runtime no recibe propuestas de delta del motor (drift, la contra
de DECISION-0019(a)).

## 2. Alcance (TASK-0061)

1. **`runtime_version`**: anadir un sello de version del motor en `protocol.config(.template)` (p.ej.
   `runtime_version`), que el master fija y la instancia del tier runtime porta. Permite detectar deltas del
   motor por version, no solo por diff de archivo.
2. **upgrade tier-aware** (py + .ps1, paridad): extender `DEFAULT_ADOPTABLE_GLOBS` con `runtime/**` +
   `.github/workflows/validate.yml`, PERO proponer deltas de `runtime/**` **SOLO si la instancia tiene
   `adoption_tier=runtime`**. Para `adoption_tier=coordination` (o ausente) el upgrade se comporta como hoy
   (no propone runtime). Excluir artefactos de ejecucion (`runtime/state/`, `runtime/runs/`, `__pycache__/`).
3. **Reporte**: el delta de runtime aparece en el reporte markdown solo para instancias runtime, con el
   `runtime_version` master vs instancia.

## 3. Invariantes

- **U1:** una instancia `adoption_tier=runtime` recibe propuestas de delta de `runtime/**` (nuevo/cambiado/
  eliminado) + el salto de `runtime_version`.
- **U2:** una instancia `coordination`/sin tier NO recibe propuestas de `runtime/**` (comportamiento actual).
- **U3:** inform-only (la adopcion sigue siendo decision de la instancia, DECISION-0006); aditivo; paridad
  py/.ps1; no se proponen artefactos de ejecucion (state/runs/pycache).

## 4. Tests (golden examples/runtime_upgrade_cases, determinista)

1. instancia runtime-tier con motor desactualizado => upgrade propone deltas de `runtime/**` + runtime_version.
2. instancia coordination-tier => upgrade NO propone `runtime/**` (solo coordinacion/scripts como hoy).
3. no se proponen `runtime/state`, `runtime/runs`, `__pycache__`.
4. inform-only: el upgrade no muta la instancia (solo reporta). + paridad py/.ps1. + CI.

## 5. Fuera de alcance

- Aplicar/mergear el delta automaticamente (sigue siendo decision de la instancia). Wrapper LLM real, D2.3,
  D2.4. Fase B, Fase 7. Cambio incompatible => blocked + DECISION.
